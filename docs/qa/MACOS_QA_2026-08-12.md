## MAC-TELEMOST-EMBED-001

Type:
Research spike — not a production implementation.

Architecture tested:
`TelemostPage` → macOS-only Tauri command → owned external-URL `WebviewWindow` (WKWebView). The existing Windows CEF path is unchanged. The MAC-001 Tauri-opener browser path remains the failure fallback.

Why this mode:
Tauri supports a child `Webview`, but the current application capability set does not grant the child-webview creation permission. The project already has established owned-window patterns. The minimal spike therefore uses a separate application-owned `WebviewWindow` rather than widening capabilities or adding a native WKWebView wrapper.

Implementation/evidence:

- macOS-only experimental control accepts a Telemost `/j/` URL and invokes `open_telemost_macos_spike`.
- The Rust command accepts HTTPS join URLs only on `telemost.yandex.ru` and `telemost.360.yandex.ru`.
- The window uses the persistent WebKit data store (`incognito(false)`), is parented to the main window, and returns focus on destruction.
- Navigations are restricted to the explicit Telemost/Yandex passport/OAuth origins. Blocked navigation and every popup are redirected through the Tauri opener.
- The remote window label is absent from application capabilities and no remote capability URL is configured; the Telemost page therefore receives no privileged Office360 IPC capability.
- `NSCameraUsageDescription` and `NSMicrophoneUsageDescription` were added to the macOS bundle plist.
- Runtime confirmed the existing MAC-001 action opens Telemost in Safari through the system-browser fallback.
- A real Telemost join URL was not present in the local calendar/database, and Safari had no active Yandex web session. No credential or OAuth token was injected.
- macOS Accessibility automation could focus the experimental controls but did not dispatch a usable React input event. Consequently creation/load of the WKWebView window was not proven in this runtime session.

## TELEMost native integration — Phase 1

The Telemost service home is now an Office360-owned React UI. It no longer treats a generic Telemost/Yandex 360 page as the macOS product surface.

- Native Join by link dialog validates a concrete Telemost `/j/` URL.
- Windows routes validated meetings to the unchanged CEF renderer.
- macOS routes validated meetings to the owned WKWebView meeting surface, with Tauri opener fallback.
- Generic Telemost/Yandex destinations are trapped and reported to the native page with Retry and Open in browser actions.
- The exact runtime-observed `yandex.ru/user-id` session-bootstrap route remains allowed; arbitrary Yandex paths and custom schemes remain denied.
- New meeting stays on the existing REST service and reports API/grant errors natively instead of opening a generic website.
- Schedule enters the native Calendar integration instead of Yandex Calendar web UI.
- DEV-only manual join field remains for QA and is absent from production builds.
