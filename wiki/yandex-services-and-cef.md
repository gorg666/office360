# Яндекс-сервисы и CEF

## OAuth и организации

Диск, Телемост и Трекер используют access/refresh token активного Яндекс OAuth-аккаунта Office360. Отдельные токены не вводятся. OAuth-приложению нужны права `cloud_api:disk.read`, `cloud_api:disk.write`, `tracker:read`, `tracker:write`, `directory:read_organization` и `telemost-api:conferences.create/read/update` в дополнение к почтовым и профильным правам.

После повторной авторизации выданные scopes сохраняются для диагностики аккаунта. Если Яндекс не вернул список scopes, доступ проверяется фактическим API-запросом. Ошибка 401 требует переподключения аккаунта, 402 означает ограничение тарифа, 403 — недостаток scope или прав пользователя, 429 — ограничение частоты запросов.

Трекер требует `X-Org-ID`. Office360 получает организации через `GET https://api360.yandex.net/directory/v1/org`, автоматически выбирает единственную и хранит выбор отдельно для каждого аккаунта. При невозможности определить организацию ID вводится на странице Трекера.

## Диск

Страница `/disk` работает непосредственно с REST API Яндекс Диска. SQLite не содержит копию каталога. Поддерживаются папки, поиск, сортировка, квота, постраничный просмотр, загрузка и скачивание, переименование/перемещение, удаление в корзину, публикация и снятие публичного доступа. После публикации ссылка копируется в буфер обмена.

## Трекер

Страница `/tracker` использует API v3 и не синхронизируется с локальными задачами Office360. Доступны мои задачи, очереди, фильтры, карточка задачи, создание и редактирование, допустимые переходы, комментарии и вложения. Очереди, статусы и приоритеты загружаются из API.

## Телемост и Chromium

REST API Телемоста доступен только Яндекс 360 для бизнеса. Office360 поддерживает создание, чтение и изменение конференций, комнату ожидания, соорганизаторов, трансляцию и автоконспектирование в пределах тарифа.

Встроенный браузер использует CEF `148.0.9+g0d9d52a`, Chromium `148.0.7778.180`, Windows x64. C++ host создаёт Chromium как дочерний HWND, а Rust загружает host через стабильный C ABI. Профиль хранится в `AppLocalData/office360/cef/telemost-profile`. При уходе со страницы HWND скрывается, сессия и cookies сохраняются отдельно от OAuth-токенов.

Навигация разрешена по HTTPS-доменам Яндекса. Внешние URL открываются системным браузером. Камера и микрофон разрешаются только origin Телемоста после подтверждения пользователя.

DOM bridge принимает только типизированные команды `getPageState`, `query`, `queryAll`, `read`, `click`, `focus`, `input`, `paste`, `scrollIntoView`, `inspect` и ограниченный `snapshot`. Произвольного `eval` нет. Bridge работает только на origin Телемоста; password-поля, URL query/fragment и атрибуты, похожие на токены или сессии, не возвращаются.

## Сборка и упаковка

```powershell
.\scripts\bootstrap-cef.ps1
.\scripts\build-cef-host.ps1
npm run tauri build
```

Bootstrap скачивает закреплённый официальный архив и обязательно проверяет SHA-256. SDK, build-каталог и staged runtime не входят в Git. В пакет Tauri включается `cef-runtime` с host DLL, subprocess, `libcef.dll`, `chrome_elf.dll`, `.pak`, locales, ICU, V8 snapshot и GPU/runtime-файлами.

Проверка payload:

```powershell
.\scripts\verify-cef-payload.ps1 -PayloadPath .\src-tauri\cef-runtime
```

Smoke после установки выполняется из чистой установленной директории: открыть `/telemost`, проверить создание профиля, запуск `office360-cef-subprocess.exe`, авторизацию, WebRTC, запрос разрешений, clipboard и DOM inspector.
